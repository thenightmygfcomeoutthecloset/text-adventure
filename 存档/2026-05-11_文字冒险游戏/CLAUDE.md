# 异界卷 · 文字冒险 — 项目上下文

## 项目概述
纯静态前端文字冒险游戏，部署于 GitHub Pages。
AI 引擎：DeepSeek Chat API（用户自备 Key，存于 localStorage）
后端：Supabase Auth + PostgreSQL（云端存档）

## 文件结构
index.html   → 所有屏幕（标题/频段/世界/角色/游戏）
游戏.js      → 核心逻辑：AI调用、身份系统、存档、云端同步
数据.js      → 静态数据：世界定义、命格、成就
样式.css     → 全局样式
管理.html    → 后台管理面板
CLAUDE.md    → 本文件（项目上下文）
supabase/schema.sql → 数据库 schema

## 关键约束
- 无构建工具，无 npm，纯原生 JS（ES6 模块语法不可用）
- 不能引入任何新的外部依赖（CDN 库除外）
- Supabase URL/Key 硬编码在 游戏.js 顶部（已有配置）
- 所有屏幕切换通过 showScreen() 函数控制
- 游戏状态存于全局变量 gameState（见 游戏.js）

## 开发规范
- 修改前先读完相关函数，不要假设函数签名
- 每次修改后检查：游客模式和云端账号模式都正常
- localStorage key 命名：deepseek_adventure_{userId}_{type}
- 不要修改 Supabase schema，只操作现有表结构
- CSS 变量优先，避免硬编码颜色值

## git 追踪规则
- *_备份.html、*_backup.html、*.bak → 不追踪，备份文件只存本机

## 版本号规则
格式：vMAJOR.MINOR.PATCH「版本代号」
- PATCH +1：bug 修复、小调整（不新增功能）
- MINOR +1：完成一个完整功能任务（本次提示词中的每个"任务"算一次）
- MAJOR +1：整体架构重构或用户体验全面升级
当前版本见 index.html 第 <p class="version-tag"> 标签和 README.md 顶部

版本代号取2-4个汉字，概括本次改动主题，例如：
  v0.6.0「重试护盾」/ v0.6.1「键盘适配」/ v0.7.0「存档升格」

## 每次任务完成后必须执行的收尾流程
完成功能开发并验证通过后，按以下顺序操作，一步不能省：

### 第一步：同步更新版本号（修改以下两处）
1. index.html → 找到 <p class="version-tag">，将版本号改为新版本
   示例：<p class="version-tag">v0.6.0「重试护盾」</p>
2. README.md → 找到第一行的版本标题或 badge，同步修改版本号
   若 README.md 无版本信息，在文件顶部"# 异界卷 · 文字冒险"下方添加：
   > 当前版本：v0.6.0「重试护盾」

### 第二步：更新 CLAUDE.md 本文件
在本文件末尾的【更新日志】章节追加一条记录（格式见下方）。
如果【更新日志】章节不存在，在文件末尾新建它。

### 第三步：Git 提交并推送
执行以下命令：
```
git add -A
git commit -m "vX.X.X「代号」：简短描述本次改动（不超过50字）"
git push origin master
```
commit message 格式严格遵守：版本号+代号在前，冒号后跟描述。
示例："v0.6.0「重试护盾」：API失败自动重试2次，区分余额/网络错误类型"

### 第四步：确认 GitHub Pages 部署
推送后告知用户："已推送到 master，GitHub Pages 将在约1分钟后自动更新。"
不需要等待部署完成，告知即可。

## 验证步骤

关键流程：标题页 → 选频段 → 选世界 → 创角色 → 游戏 → 存档
游客模式和云端账号模式都要过一遍
